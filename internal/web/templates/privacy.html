Privacy

ghook is self-hosted software that can serve many Google accounts on one instance. This instance is run by its operator, on the operator's own server.

ghook reads Gmail metadata so it can route notifications to the webhooks you configure. A message body is fetched only when a webhook is explicitly set to include it, and it is not kept unless you turn retention of bodies on. Delivery logs keep metadata (message id, route, target, status, timing) by default.

Each signed-in user sees only their own mailboxes, routes, targets, deliveries and settings. ghook does not sell data. ghook does not share a user's data with anyone except the webhooks that user configures.

This is not end-to-end encryption. ghook has to process mail in memory to decide which webhook to call. Google tokens, target secrets, route match fields, and any stored payloads are encrypted at rest with a per-user key that is wrapped by the operator's instance key. The operator who has both the database and that instance key can decrypt those fields. A copy of the database file without the instance key cannot. Login and mailbox addresses stay in the clear because they are used to look up incoming notifications.

A webhook can be given an age public key so the posted body is encrypted for the receiver. ghook still sees that body in memory before it encrypts the POST. Running the process in a confidential VM is a possible later hardening; this version does not do that.

You can sign out, or delete your account and data, from the account page. Deleting an account destroys the per-user key and then deletes the rows, so leftover ciphertext cannot be opened. There is no separate ghook account service.
